### 🟢 前沿研究

![SkillCoach自进化评分框架](../data/images/cards/2026-07-04/item-3.png)

1. **SkillCoach（用于评估和提升 Agent 技能使用能力的研究框架）提出“会自我进化的评分标准”。**
这项研究盯上的不是模型“答对了没”，而是它到底会不会**正确调用技能**、会不会越用越熟练 💡。从标题看，作者把 **rubrics（评分量表，像面试打分表那样把好坏拆成可比较的标准）**做成可自我迭代的机制，用来评估并增强 **agentic skill-use（Agent 在真实任务里调工具、分步骤解决问题的能力）**。这类方向很关键，因为未来企业买的未必只是“会聊天”的模型，而是能稳定完成流程工作的 Agent 🚀。可先看 [论文摘要页(briefing)](https://huggingface.co/papers/2607.01874)。

2. **AnyGroundBench（面向视频定位任务的专业评测集）瞄准视觉语言模型的“看视频找目标”能力。**
这篇工作聚焦 **video grounding（视频定位，让模型在一段视频里找出某个对象或动作具体出现在哪里）**，而且还是 **specialized-domain benchmark（面向特定专业场景的测试基准，不是泛泛而谈的通用题库）**。它的意义在于，很多模型在通用演示里看着很强，但一进细分行业视频场景，能力是否靠谱往往没人说得清 🤔。如果你关心安防、工业巡检、内容审核这类视频业务，这种评测会直接影响“模型能不能上生产环境”。更多可见 [论文摘要页(briefing)](https://huggingface.co/papers/2607.02269)。

3. **英国 AI Security Institute（英国人工智能安全研究机构）称常见基准测试低估了 Agent 真实能力。**
这项发现的重点很直接：很多**标准 benchmark（基准测试，用来统一比较模型能力的考试题）**测出来的分数，可能没把 Agent 真正能做的事情算进去 📉。报道指出，现有评测体系会**系统性低估** AI agents（能自主拆解并执行任务的 AI 助手）的实际表现，这对行业判断风险和能力上限都很关键。换句话说，企业如果只看公开榜单，可能会错判哪些任务已经可以交给 Agent 去做了 ⚠️。详情见 [完整报道(briefing)](https://the-decoder.com/uks-ai-security-institute-finds-standard-benchmarks-systematically-underestimate-what-ai-agents-can-actually-do/)。

4. **AgenticSTS（测试长流程 Agent 的有限记忆实验平台）专门考模型“记不住太多时还能不能把事做完”。**
这篇研究关注 **long-horizon LLM agents（需要连续完成很多步任务的大模型 Agent）**，并把 **bounded-memory（有限记忆，指模型不能无限保存上下文，像人工作时也会遗忘细节）** 设成核心约束。这个问题很贴近真实办公：任务一长、信息一多，Agent 就容易前后矛盾、漏步骤或忘目标 😵。如果这类测试成熟，未来大家评估 AI 助手时就不能只看“单题表现”，还要看它在复杂流程里能不能一路稳定收尾。可参考 [论文摘要页(briefing)](https://huggingface.co/papers/2607.02255)。

5. **EvoPolicyGym（评估自主策略进化能力的交互环境）把 Agent 拉进“边做边学”的考场。**
从标题看，这项工作研究的是 **autonomous policy evolution（自主策略进化，指 Agent 在反复交互中自己调整做事策略）**，并放在 **interactive environments（交互环境，会根据行动变化反馈的任务场景）** 里评估。它不只是问模型“这题会不会”，而是问它能不能在持续试错后变得更聪明 🧠。这对自动运营、流程自动化、游戏 AI 或机器人控制都很重要，因为现实任务很少是一锤子买卖。更多信息见 [论文摘要页(briefing)](https://huggingface.co/papers/2607.02440)。

6. **Bridgewater（桥水基金，全球知名对冲基金）的金融测试让 GPT 和 Claude 集体失分，暴露“公开答案依赖症”。**
这篇报道的核心结论很值得细想：模型没做好，并不一定只是“能力不够”，还可能因为测试题的**正确答案从未公开**，模型缺少可直接模仿的现成材料 📚。这触到一个现实问题——很多大模型擅长处理互联网上已有共识的问题，但碰到机构内部知识、私有判断框架或稀缺数据时，表现会明显下滑。对企业来说，这意味着想让 AI 真正在金融、法务、咨询等知识密集岗位发挥价值，**专有数据**和**领域评测**会越来越重要。可查看 [完整报道(briefing)](https://the-decoder.com/gpt-and-claude-failed-bridgewaters-finance-tests-because-the-right-answers-were-never-public/)。

7. **Program-as-Weights（一种把“程序”当作模型权重来表达模糊函数的新范式）尝试改写模型表达方式。**
这篇论文提出一种新思路：把 **weights（权重，决定模型如何处理输入的内部参数）** 和 **programming paradigm（编程范式，也就是“如何组织计算逻辑”的基本思路）** 联系起来，用来表示 **fuzzy functions（模糊函数，适合处理边界不清、非黑即白不好定义的问题）**。虽然标题偏学术，但它讨论的是一个很底层的问题：模型的“知识”是否能用更可控、更像程序的方式来组织。若这类方向走通，未来 AI 可能更容易解释、修改，甚至更适合进高要求行业场景。可先看 [论文摘要页(briefing)](https://huggingface.co/papers/2607.02512)。

8. **PACE（用于评估 Agent 能力的代理指标）想先用“替身测试”快速判断 Agent 水平。**
这项研究里的 **proxy（代理指标，指不直接测最终能力，而用一个更快、更便宜的替代指标来估算）** 很有现实意义，因为完整评测 Agent 往往既慢又贵 ⏱️。PACE 试图为 **agentic capability evaluation（Agent 能力评估）** 找到一种更轻量的判断方式，让研究者和企业更快知道模型大概处在什么水平。要是这种方法有效，未来选型、采购、内测都会更高效，不必每次都搭一整套复杂任务环境。详情可见 [论文摘要页(briefing)](https://huggingface.co/papers/2607.02032)。
